# 11 · 逐条抬升方法论（怎么把剩下的缺口做完）

这份文档是给"继续做"用的：工具已经齐了，剩下的是按清单一条条读汇编、写代码。

## 工具链

| 工具 | 作用 |
|---|---|
| `tools/macho_objc.py` | 解析 Mach-O：类/方法/ivar/属性、chained fixup 指针解码 |
| `tools/disasm_annot.py` | **核心**：反汇编并标注——stub→选择器/导入符号、adrp+add→字符串/类、imp→`-[类 方法]` |
| `tools/call_coverage.py` | 证据保真度：二进制实际调用的 selector/符号/字符串，源码里有没有等价表达 |
| `tools/worklist.py` | 按指令权重输出待还原清单（`docs/10`） |
| `tools/restore_score.py` | 指令加权还原度（旧口径，保留作对照） |
| `tools/source_check.py` | 结构体检（括号、`@interface/@implementation/@end`、import 可达） |

## 标注器为什么能做到"看得懂"

三个关键点（都是实测解出来的）：

1. **`__objc_stubs` 每个条目自带选择器**
   ```
   adrp x1, selref ; ldr x1,[x1,#off] ; adrp x16,got ; ldr x16,[x16,#off] ; br x16
   ```
   所以 `bl 0xa46a0` 直接就是 `send defaultManager`。

2. **导入符号来自 dyld chained fixups**
   GOT 槽是 `PTR_64_AUTH`（bit63=1），**ordinal 在低 16 位**；普通 `PTR_64` bind 的 ordinal 在低 24 位。
   用 `LC_DYLD_CHAINED_FIXUPS` 的 imports 表就能把每个槽解成 `_CFRelease` / `_objc_msgSend` / `_posix_spawn`。

3. **常量传播**：`adrp x8,#page` → 记住页基址；`add x8,x8,#off` → 拼出 VA，
   落在 `__cfstring` 就标 `@"…"`（`model.json` 的 `grid/uvBox/texture/blend` 就是这么读出来的）。

## 一条方法的抬升流程

```bash
# 1) 先看清单里的名字，定位指令数与方法签名
python3 tools/disasm_annot.py --class WNPainter --sel paintOverlayForRig:background:context: --brief

# 2) 需要看细节时去掉 --brief，逐条对照 imp 偏移
python3 tools/disasm_annot.py --class WNPainter --sel paintOverlayForRig:background:context:

# 3) 写实现：把每一步对应成一行源码，并在注释里标回原地址
# 4) 结构体检
python3 tools/source_check.py

# 5) 复测证据保真度（该方法应接近 100%）
python3 tools/call_coverage.py --class WNPainter --verbose
```

## 已经按这个流程做完的（可当范例）

| 方法 | 指令 | 关键还原点 |
|---|---|---|
| `WNRenderer meshesForParts:` | 361 | `uvBox=[u0,v0,u1,v1]`；顶点 `(cols+1)*(rows+1)`；索引 **uint16**、每格 6 个；`indexCount=len>>1`；`positionOffset` 按顶点字节累加；`multiply` 来自 `blend=="multiply"` |
| `WNRenderer setStageSize:` | 59 | NaN/inf/非正/未变化四重提前返回；quad 8 float = `{0,0,w,0,0,h,w,h}`；清 `glowSurfaces` |
| `WNRenderer liveFigureBounds` | 74 | 遍历 positions 的 float2 求 AABB；`<8` 字节 → `CGRectNull`；NaN 跳过 |
| `WNRenderer drawMesh:positions:textureObject:look:encoder:` | 91 | **真实 ABI 是 80 字节 `Appearance` 指针**：`setFragmentBytes:0x50 atIndex:0`；`drawIndexedPrimitives` 三角形/UInt16/offset 0 |
| `WNRenderer encodeClip:` | 591 | 共享 positions buffer + `space=(w,h,offx,offy)` atIndex:2；逐 mesh 组 `WNLook`（tint 来自 `liveTint`） |
| `WNLiveRig renderPointToStage:` | 127 | transform 的 `ax/ay/kx/ky/rot/AX/AY`；缩放单位 **10000**；`rot` 是 0.1 度；`AY` 四舍五入到 0.1；`out = (AX + dx·cos − dy·sin, AY + dx·sin + dy·cos)` |

> `Appearance` 结构（80 字节）：
> ```c
> struct { float4 tint; float alpha, pad0, pad1, pad2;
>          float4 clipX; float4 clipY; float4 clipRect; };
> ```
> `clipX.w > 0.5` 才启用矩形剪裁；`tint.a` 为 mix 权重（发色的 shader 通道就在这里）。

## 剩余清单怎么读

`docs/10_待还原清单.md` 给出 150 个方法、约 6.3 万条指令，按权重排序，每条都带"缺什么证据"。
按下面的顺序做效率最高（同一子系统共享读法）：

1. **渲染**：`WNPainter`（overlay/eye/shadow/sprite）、`WNHitMask.newPath`、`WNLiveRig`（`point:deformer:`、`prepareDeformers`、`updateMesh`、`compileMesh`）
2. **资源**：`PDAssetManager`（`status:progress:`、`configureActive:…`、`advance`）
3. **AX 抓取**：`PDNative_MCPAXAttributeBridge` / `PDNative_MCPAXNodeSource` / `PDNative_MCPUIElementSerializer`
4. **App 管理**：`PDNative_AppManager`（`installDebPackage:`、`fakesign…`、`installApp:`、`openURL:`）
5. **对话编排**：`PDChatService`（`runNextTool`、`requestRound`、`handleDataMaintenanceRequest:`）、`PDAIPetRuntime.executeTool:arguments:completion:`
6. **其余**：`PDSoundPlayer.notesForSound:arguments:`、`PDNative_ClipboardManager`、`PDVoice*`

## 判定"做完"的标准

同一条方法同时满足：

1. `tools/call_coverage.py` 里该方法证据保真度 ≥ 95%
2. 关键常量（缩放单位、阈值、颜色、路径）在源码注释里标了来源地址
3. `tools/source_check.py` 通过
4. 分支结构（提前返回的边界条件）与二进制一致（例如尺寸 NaN 保护、`indexCount` 的 `>>1`）

只做到 1 不做 2/4，就会出现"看起来一样、边界行为不同"的假还原——这正是上一轮比例从 99.8% 掉到 66.3% 的原因。
