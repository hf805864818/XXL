# 09 · 故障排查

排查顺序建议：**能不能装 → 出不出得来 → 长得对不对 → 点不点得动 → 改得动不动**。

## 0. 先确认加载了

```bash
ssh root@手机IP
# 插件是否被 SpringBoard 加载
ps aux | grep -i springboard | head -2
ls -l /Library/MobileSubstrate/DynamicLibraries/PetDFY.dylib
# 结构是否完整
plutil -p /Library/MobileSubstrate/DynamicLibraries/PetDFY.plist    # Filter → com.apple.springboard
```

看日志：

```bash
# 统一日志（iOS 15+）
log stream --predicate 'eventMessage CONTAINS "[PetDFY]"' --level debug
# 或旧式
tail -f /var/log/syslog | grep PetDFY
```

自己加的调试输出直接用 `NSLog(@"[PetDFY] …")`，会进同一条流。

## 1. 装不上 / 装了没反应

| 现象 | 检查 |
|---|---|
| `dpkg` 报依赖缺失 | `Depends: mobilesubstrate, firmware (>= 14.0)`；确认越狱环境（Dopamine/palera1n 的 rootless 请用 roothide 路径） |
| 装上但设置里没有条目 | `layout/Library/PreferenceLoader/Preferences/PetDFYPrefs.plist` 是否装到位；`PreferenceBundles/PetDFYPrefs.bundle` 权限 755 |
| respring 后角色不出现 | `Enabled` 是否为 1；`PDLayoutConfig` 是否读到了坏 JSON（坏 JSON 会整份退回默认，不会崩） |
| 设备是 arm64e 但加载失败 | `ARCHS` 匹配问题；先只编 `arm64` 验证 |

## 2. 出来了，但看不见 / 位置不对

| 现象 | 原因 |
|---|---|
| 完全透明 | `PetOpacity` = 0（PDFYEnhance）；或 `PetScope=home` 且当前在前台 App |
| 在屏幕外 | `PDLayout.json` 的 `offsetX/offsetY` 过大；`anchorX` 越界 |
| 巨大/极小 | `Size` 与 `pet.scale` 相乘，两边都拉满会爆 |
| 只有阴影或只有一块 | 贴图解析失败 → 见第 3 节 |

快速复位：

```bash
ssh root@手机IP 'rm -f "/var/mobile/Library/Application Support/PetDFY/PDLayout.json"; killall -9 SpringBoard'
```

## 3. 缺图 / 花图 / 错位

```bash
# 设备上的素材体检（把路径换成设备路径，脚本是纯标准库，可以直接在手机上跑）
python3 tools/validate_assets.py --root "/Library/Application Support/PetDFY.bundle"
```

| 现象 | 原因 | 处理 |
|---|---|---|
| 某块空白 | `tex` 名字不等于文件名，或不在候选链里 | 用校验器的 `缺：` 列表逐个补 |
| 花屏/颜色错 | PNG 不是 8bit RGBA（调色板/灰度） | 用图像工具导出为 RGBA8 |
| 贴图错位 | 画布尺寸与模板不一致 | 拿原图当画布尺寸重画 |
| 层级穿模 | `z` 冲突 | 相邻部件留 0.05 以上 |
| 主题下缺服装图 | 主题目录只有 `tex/feat` | 会自动回退 `originals/`；若仍缺说明该服装的 `src` 写错 |

## 4. 点不点得动

| 现象 | 原因 |
|---|---|
| 完全点不到 | `Interactive=0`；或 `alphaThreshold` 过高（命不中蒙版） |
| 只有中间一块能点 | `interaction.padding` 负值；或 `buildsInteractionPath` 被关 |
| 长按不出菜单 | `LongPressAction=none`；`PDLayout.json` 的 `gesture.long` 也是 `none` |
| 拖动没反应 | `interaction.drag` 阈值相对屏幕尺度太大 |

命中判定读的是渲染出来的 alpha 蒙版（`WNHitMask`），所以**贴图 alpha 就是点击区域**——
画了一张"看不见但 alpha 不透明"的图，会出现"点空气也有反应"。

## 5. 换衣服/主题不动

| 现象 | 原因 |
|---|---|
| 点了没变化 | 该服装 `parts` 为空或缺贴图 → `tools/add_outfit.py --dry-run` / 校验器 |
| 提示 unknown outfit | 目标 id 不在目录里（`live/model.json` 的 `models` 键 + `outfits/` 目录） |
| 设置里改了不生效 | 需要重启 SpringBoard 才彻底生效？不应该——已挂 Darwin 通知热重载；若无效检查 `com.susudear.petdfyprefs/saved` 是否被偏好包发出 |
| 换主题后继续显示旧色 | 贴图 NSCache；用命令 `assets` 或 respring |

## 6. 发色不生效

逐步排查：

```bash
# a) 开关与取值是否写进去了
plutil -p /var/mobile/Library/Preferences/com.susudear.petdfyprefs.plist | grep -i hair

# b) 贴图本身能不能被染（电脑上验证同一算法）
python3 tools/recolor.py -i assets_src/originals/tex/hair_back.png -o /tmp/t.png --preset sakura
```

| 现象 | 原因 |
|---|---|
| 开了没变化 | 部件 id 不在 `defaultHairParts` 且名字里没有 `hair` |
| 线稿被染 | `HairTintSmooth` 关了，或线稿不够黑（v>0.10） |
| 一整块纯色 | `HairTintStrength` 太高且原图接近灰阶 → 降到 60–80 |
| 彩虹很卡 | `HairTintSpeed` 太高；或把 `PDHairTint` 的 `_refreshInterval` 从 1/8 调到 1/6 |
| 换装后掉色 | 检查 `resetLiveWithScheme:` 是否调到 `pdApplyHairTintForParts:`（该方法末尾） |

## 7. 布局文件改了没用

```bash
python3 -m json.tool "/var/mobile/Library/Application Support/PetDFY/PDLayout.json" > /dev/null && echo 语法OK
```

`PDLayoutConfig` 的行为是：**JSON 解析失败 → 整份忽略，用默认值**（不会崩，也不会告诉你）。
所以"改了没反应"最常见就是语法错。合并规则是深合并，你只写要改的键即可。

## 8. 崩溃了

```bash
ls -t /var/mobile/Library/Logs/CrashReporter/*.ips | head -3
cat "$(ls -t /var/mobile/Library/Logs/CrashReporter/SpringBoard*.ips | head -1)" | head -60
```

关注这几类：

| 崩溃特征 | 常见原因 |
|---|---|
| `NSException: Missing outfit %@` | `Outfit` 值指向不存在的服装（新版会用目录校验后回退） |
| `InvalidClip` | `live/model.json` 结构坏了（缺 `parts` 或 positions 字节数不匹配） |
| `MTLTexture` 相关 | 贴图尺寸 0 或非 RGBA |
| 启动即崩 | `Whale.metal` 编译失败（`newLibraryWithSource:` 报错会打 `[WNRenderer] ShaderError`） |

## 9. 我的改动到底改了哪儿（自查清单）

```bash
cd PetDFY_Editable
git status --short 2>/dev/null || true      # 若已 git init
python3 tools/source_check.py               # 语法/结构体检
python3 tools/validate_assets.py --root assets_src
python3 tools/pack_assets.py --src assets_src --verify
```

代码侧改动集中在这些文件（其余是还原件）：

```
src/Ext/PDHairTint.{h,m}           发色引擎
src/Ext/PDHairTintPanel.{h,m}      发色面板
src/Ext/PDOutfitCatalog.{h,m}      服装目录
src/Ext/PDTextureResolver.{h,m}    素材定位
src/Ext/PDLayoutConfig.{h,m}       布局配置
src/Ext/WNRenderer+HairTint.{h,m}  渲染器注入
src/Core/PDOverlayController.m     dress/hair 分支、布局、通知
src/Core/WNRenderer.m              texture: 优先 liveTextures；resetLive 注入
src/Core/WNLiveRig.m               textureForPart:/featurePath: 走解析器
src/Core/PDPreferences.m           服装/主题不再写死白名单
layout/.../Root.plist              新增「发色」分页
```

改回原样只需把上面这些文件恢复成 `packaging/` 里的原版二进制（或对照 `docs/07` 的注释标记）。
