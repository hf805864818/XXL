# 03 · 添加新素材（贴图 / 表情 / 主题 / 素材包）

素材分四类，落点不同。先看这张表，再动手。

| 想加的东西 | 放哪里 | 需要什么 |
|---|---|---|
| 身体/头发/衣服的贴图 | `originals/tex/<名字>.png`（或某套服装的 `originals/outfits/<服装>/`） | 8bit RGBA PNG，画布尺寸与原点对齐 |
| 表情（眼/嘴/高光/腮红） | `originals/feat/<名字>.png` | 同上，眼部件按 `_ball/_iris/_rim/_lash` 命名规则拆层 |
| 新的品牌配色主题 | `originals/schemes/<主题名>/tex/*.png` + `feat/*.png` | 可以只放差异图，缺的自动回退 `originals/` |
| 一整套素材包（给「从文件导入 ZIP」用） | `tools/pack_assets.py` 产出 | 需要 `manifest.json` + `asset-spec.json` |

## 硬性约束（违反就渲染错，不是玄学）

1. **8bit RGBA**（colortype=6，非隔行）。调色板 PNG 会让 alpha 语义丢失
   ```bash
   python3 tools/validate_assets.py --root assets_src   # 会直接报 colortype 不符
   ```
2. **画布尺寸与原图一致**。每个 part 的绘制区域来自 `model.json` 里的 `box`，
   图被裁小/放大不会自动补偿 → 角色会"错位"或"缺口"
3. **不要给贴图加阴影/描边**。描边是模型层（`brows`、`eye_creases` 等独立 part）画出来的
4. **透明区域保持真透明**（alpha=0），不要填白底——否则会盖住下层
5. 文件名 = part 的 `tex` 字段（不是 part id）。`model.json` 里 `tex` 和 `id` 可以不同
   （例：`{"id":"ponytail","tex":"crew_ponytail"}` → 读 `crew_ponytail.png`）

## 改一张现有贴图（最常见）

```bash
# 1) 本地改：originals/tex/bangs.png
# 2) 推设备（保持相对路径）
scp assets_src/originals/tex/bangs.png \
  root@手机IP:"/var/mobile/Library/Application Support/PetDFY.bundle/originals/tex/bangs.png"
# 3) 刷新：长按宠物 → 发色面板「应用」会重建缓存；或
ssh root@手机IP "killall -9 SpringBoard"
```

## 加一个表情

表情由 `feat` 目录 + `model.json` 的 `tables` 驱动。以"惊讶"为例：

1. 出图：`surprised_eyeL.png` / `surprised_eyeR.png` / `surprised_mouth.png`
   （官方已有的命名规则：`<表情>_eyeL|eyeR|mouth`，眼睛另需 `_ball/_iris/_rim/_lash` 分层时按 `tables` 里的 sprites 表）
2. 放到 `originals/feat/`
3. 让表情表认识它：在 `live/model.json` 的 `tables.faces` / `tables.MOOD` 里加键
   （`tables` 是"表情名 → 参数"的映射，具体字段见 `docs/08`）

改完用 `PDHairTintPanel` 面板或 `assets` 命令刷缓存。

## 做一个主题（配色变体）

```bash
cp -R assets_src/originals/tex   assets_src/originals/schemes/mytheme/tex
cp -R assets_src/originals/feat  assets_src/originals/schemes/mytheme/feat
# 只改你想变的图（例如头发、衣服主色），其余留着让它回退
```

然后在设置里选主题，或直接命令行：

```bash
# 主题值就是目录名，不需要注册
defaults write com.susudear.petdfyprefs Scheme -string "mytheme"   # 设备上执行
```

> 主题目录在官方包里位于 `originals/schemes/<名>/`，而二进制模板拼的是 `schemes/<名>/`。
> `PDTextureResolver` 两级根都试（主题根 → `originals/`），所以你放哪儿都能读到。

## 打成一包素材 ZIP（走 App 内「从文件导入 ZIP」）

官方格式（已逐字节验证可复现）：

```
PetDFY-assets.zip       只含 originals/ 与 live/，路径原样
asset-manifest.json     { asset_version, content_sha256, files{path:{bytes,sha256}} }
asset-spec.json         { schema:1, file, bytes, sha256, manifest_sha256, asset_version }
```

生成：

```bash
python3 tools/pack_assets.py --src assets_src --out build/assets
# 输出 build/assets/{PetDFY-assets.zip, asset-manifest.json, asset-spec.json}
```

关键公式（从原包反推、已验证）：

```
content_sha256 = sha256( 拼接( 对文件按路径排序: "<path>:<sha256>\n" ) )
asset_version  = content_sha256 的前 16 个字符
```

验证方式（不带改动时应输出"一致 ✅"）：

```bash
python3 tools/pack_assets.py --src assets_src --verify
# 文件数 497，合计 16435128 字节
# content_sha256 = ad294eba347cbc4348931f5854760104c4d670e88536c6a3c8be2cf791c8ce63
# asset_version  = ad294eba347cbc43
```

## 用户素材包（不动官方包也能加图）

运行时会额外读两个目录：

```
/var/mobile/Library/Application Support/PetDFY/UserPacks/
/var/mobile/Library/Application Support/PetDFY/AssetImports/
```

命中顺序在官方包之后（覆盖优先），可以把单张 PNG 直接丢进去，例如：

```bash
mkdir -p "/var/mobile/Library/Application Support/PetDFY/UserPacks/tex"
cp my_bangs.png "/var/mobile/Library/Application Support/PetDFY/UserPacks/tex/bangs.png"
```

## 检查清单

```bash
python3 tools/validate_assets.py --root assets_src
# ✓ 4 套服装 × 8 主题全绿，且「发色可用性 8/8」
```

出现 `缺：xxx` 就说明该 part 的贴图在候选链里一个都没命中：
检查文件名是否等于 `tex` 字段、是否在 `originals/tex` 或该服装目录、扩展名是否 `.png`。
