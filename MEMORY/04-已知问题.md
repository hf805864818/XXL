## 五、编译期错误全景（2026-11-24，11 轮 CI 收敛记录）

**结论先说**：T3 源码是"逆向阅读稿"，不是"编译通过稿"。41,245 行里没有一个文件被 clang 检查过。
头文件闭环（#import 都能找到）不等于能编译 —— `.m` 内部还有大量私有方法没声明、`return` 后面留着旧实现。

下面 11 类问题是实际踩出来的，按出现顺序：

| # | 报错 | 根因 | 修法 | 文件 |
|---|---|---|---|---|
| 1 | `'PetDFY.h' file not found` | theos 默认不把 `src/` 加进 `-I` | `CFLAGS` 加 `-Isrc -Isrc/Core -Isrc/Sources -Isrc/Ext` | `Makefile` |
| 2 | `property ... does not match type of accessor` | 逆向时 getter/setter 类型抄得不一致 | 统一 ivar/property/getter/setter/实现四处类型 | `PDChatController.h/.m`、`PDChatService.h/.m`、`PDCloudVoiceInput.h`、`PDComposerTextView.h` |
| 3 | `'ApplicationServices/ApplicationServices.h' file not found` | iOS SDK 没有 macOS 的 AX umbrella | 写 `shim/ApplicationServices/ApplicationServices.h`，只放编译期声明，符号走 dlsym | `shim/` |
| 4 | `use of undeclared identifier 'context'/'image'/'glowImage'` | `return` 之后残留旧实现 | 删掉死代码块 | `WNPainter.m`（18 处） |
| 5 | `redefinition of 'notes'/'frames'/'out'` | 同上 | 同上 | `PDSoundPlayer.m`（6 处） |
| 6 | `use of undeclared identifier 'milliseconds'` | 同上 | 同上 | `WNMotion.m`（1 处） |
| 7 | `no visible @interface ... declares the selector 'X'` | 方法被调用但既无声明也无实现（逆向遗漏） | 补 `category` 声明 + 安全空实现（`PDStubs.m`，打 `[PDStub]` 日志） | `PDPetView.h`、`WNRenderer.h`、`Ext/PDStubs.m`（12 个方法） |
| 8 | `cast of 'id' to 'CGPathRef' requires a bridged cast` | ARC 要求显式 bridge | `(__bridge CGPathRef)` | `PDPetView.m` |
| 9 | `incompatible block pointer types` | block 参数类型与属性声明不符 | 按真实签名改（如 `void(^)(NSString*, CGPoint)`） | `PDPetView.m`、`PDSoundPlayer.m` |
| 10 | `CGPoint` / `CGSize` 互串 | 属性是 `CGSize`，调用处当 `CGPoint` 用 | 显式构造转换 | `PDPetView.m` |
| 11 | `ld: library not found for -lsubstrate` | GitHub runner 没有 libsubstrate | 删 `PetDFY_LIBRARIES`，只用 `-Wl,-undefined,dynamic_lookup`；Package 步骤改 `always()` | `Makefile`、`build.yml` |

### 复查清单（以后改源码再编译时）

```bash
# 1) 死代码：return 之后还有代码
grep -n -A3 "return .*;" src/**/*.m | grep -B1 -A2 "^\s*CGContext\|^\s*NSArray\|^\s*NSUInteger"

# 2) 属性声明一致性：同一 selector 在 .h 出现多次
grep -n "set[A-Z].*:" src/**/*.h | sort | uniq -d

# 3) 调用了但没定义的方法（需要 stub 或补实现）
python3 tools/gen_private_decls.py   # 见 work/gen_decls2.py
```

### 教训

1. **不要把"逆向还原完整"当成"能编译"** —— 两者差 40+ 处修补
2. **`-Isrc` 是第一个坑**：伞形头 `PetDFY.h` 在 `src/` 根，theos 不会自动加
3. **`return` 后的死代码是这批源码的通病**，几乎每个大文件都有，删的时候注意方法边界（找顶格 `}`）
4. **缺方法的补法**：声明放类头（所有 importer 可见），实现放独立 category `.m`，返回 nil/0 + 日志
5. **链接期不要 -lsubstrate**：越狱环境运行时提供，CI 上没有

## 六、打包类坑（dpkg 层面，不是编译问题）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| P1 | `unable to create '.../x.dpkg-new': No such file or directory` | tar 只有文件条目、没有目录条目 | 打包时先写 `TarInfo(type=DIRTYPE)`（父在前），再写文件 |
| P2 | `duplicate value for 'Installed-Size' field` | theos 的 `dm.pl` 打包时**自动追加** `Installed-Size`；手写 control 里也有一行 → 两行都进包，dpkg 视为 **fatal** 而不是 warning | control 里**不要写** `Installed-Size`，交给 theos 算 |
| P3 | `dpkg: warning: downgrading ... from 0.1.8-e1+build.022 to 0.1.8-b1` | 版本号字母序倒退（`b` < `e`） | 新包版本号必须高于已装版本 |
| P4 | dpkg 解包报 `parsing file ... near line N` | control 格式问题（重复字段、缺主字段、行过长） | 打包前用 `dpkg-deb -I` 自检 |

**教训**：P1 和 P2 都是"我自己手搓打包器 / 手写 control"引出来的。能用 `dpkg-deb -b` 就别手搓；用 theos 打包就别在 control 里重复填它自动生成的字段。
