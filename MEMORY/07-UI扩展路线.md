# 07 · UI 扩展路线

> 结论：**不动设置页二进制，新 UI 全部做成运行时面板。** 对应决策 D-12。

---

## 1. 设置页那个 846 KB 是什么

| 项 | 实测 |
|---|---|
| 路径 | `layout/Library/PreferenceBundles/PetDFYPrefs.bundle/PetDFYPrefs` |
| 大小 | 846,688 B |
| 架构 | fat：arm64 + arm64e |
| 类型 | Objective-C，无 Swift 段，无壳无加固 |
| 自定义类 | **18 个** |
| 方法 | 439 条（566 个 selector 引用） |
| 系统类引用 | 62 个（`PSListController`、`UITableView` ×100） |
| 内嵌文案 | **100,428 字节 UTF-16**（含 AI 工具定义 JSON） |
| 符号 | 293 个导出（strip 过） |

作用：被 PreferenceLoader 加载进 `Preferences` 进程，画「设置 → 大肥鱼」的整个界面。

---

## 2. 能重编吗？能，但三个坎

| 坎 | 风险 | 严重度 |
|---|---|---|
| 私有框架 | `PSListController` / `PSViewController` / `PSSpecifier` 是 Apple 私有，头文件要自建，ABI 错一字段即崩 | 高 |
| 签名 | Preferences 进程要求正确签名；历史事故：改名后没重算 CodeDirectory → **设置页点不进去** | 高 |
| 偏好键 | 18 个类读写几十个 `CFPreferences` 键，必须与主 dylib 完全一致 | 中 |

**隐性风险**：设置页坏掉 = 用户失去唯一可改配置的入口，只能卸载重装。

工作量：约 1–2 周（18 类 / 439 方法 + 100 KB 文案提取）。

**结论：不做。** 除非设置页本身有 plist 改不了的硬伤。

---

## 3. 运行时面板路线（现成范本）

`Ext/PDHairTintPanel.h` 的原注释就是设计说明：

> 为什么做在运行时而不是设置 App 里：设置 App 的偏好包是编译好的二进制，改它要重编 846 KB 的 PetDFYPrefs；而这个面板挂在桌宠自己的窗口上，源码完全在我们手里，滑一下立刻能看到效果，还能做「预设色板」。
> 设置 App 里同样有发色分页，两处写的是同一组 CFPreferences 键，互相看得见。

### 3.1 面板清单

| 面板 | 职责 | 关键控件 | 数据源 | 状态 |
|---|---|---|---|---|
| `PDHairTintPanel` | 发色（HSV + 预设） | 滑杆 + 色板 | CFPreferences `HairTint*` | ✅ 已有 |
| `PDCharacterPanel` | 角色切换（小白龙 / 骨骼角色） | 列表 + 缩略图 | `Characters/` 目录 + `live/model.json` | 待写 |
| `PDClipPanel` | 116 组动作浏览/试播 | `UICollectionView` 网格 | `clips.plist` + `frames/` | 待写 |
| `PDAssetPanel` | 素材导入/删除/预览 | 列表 + 导入按钮 | `PDZip` + 素材目录 | 待写 |
| `PDModelPanel` | 模型刷新/选择 | 列表 + 输入框 | Provider 配置 + `/models` 接口 | 待写 |

### 3.2 入口

`Core/PDOverlayController.m` 的 `hoverActions` 数组 + tag 分发（现有 7 路：`chat`/`voice`/`roam`/`sound`/`theme`/`dress`/`hide`）。

加三路：

```objc
// 数组里插
@"clip", @"character", @"asset"

// 分发里加
if ([action isEqual:@"clip"])      { [PDClipPanel presentInWindow:self.window]; return; }
if ([action isEqual:@"character"]) { [PDCharacterPanel presentInWindow:self.window]; return; }
if ([action isEqual:@"asset"])     { [PDAssetPanel presentInWindow:self.window]; return; }
```

## 4. 面板 vs 设置页：能力对照

| 想做的事 | 设置页（plist） | 运行时面板 |
|---|---|---|
| 静态选项 / 开关 / 滑块 | ✅ | ✅ |
| 动态列表（扫目录） | ⚠️ 只能安装时静态化 | ✅ |
| 缩略图网格 | ❌ | ✅ |
| 实时预览（滑一下就变色） | ❌ | ✅ |
| 内嵌日志/诊断 | ❌ | ✅ |
| 改动成本 | 改 plist 即可 | 写代码，但都是新文件 |
| 出问题的影响面 | 设置页可能打不开 | 面板不出现，主功能不受影响 |

**最后一行是关键**：面板出问题，桌宠照常跑；设置页出问题，用户没法自救。

---

## 5. 设置页保留什么

`layout/.../Root.plist` 现有 46 项，保留：

- 分组与标题
- `PSSwitchCell` 开关（启用、触摸互动、发色、键盘避让…）
- `PSLinkListCell` 静态列表（手势映射、配色 8 项、服装 15 项、帧率、透明度、活动范围）
- `PSSliderCell` 滑块（角色大小、底部间距、发色 HSV）
- `PSLinkCell` 子页跳转（供应商、设备操控、对话声音、下载）

**服装白名单 4 → 15 项的改动就在这里做**（e3），不需要重编二进制。

## 6. 什么时候回头重编设置页

| 场景 | 处理 |
|---|---|
| 加「角色」「动作库」「素材管理」入口 | 面板做 |
| 改分组/文案/默认值 | 改 plist |
| 设置页有硬伤（布局错乱、某项点不动） | 才考虑重编 |
| 想彻底换设计 | 那是重写，另立项目（e8 评估） |

重编前置条件（缺一不可）：

1. 有可回退的原版二进制备份；
2. 在测试机上验证过"改坏能 `dpkg -i` 回退"；
3. `ldid` 重新签名且 Preferences 进程能正常加载；
4. 所有 `CFPreferences` 键与主 dylib 逐条对齐（写脚本比对）。
