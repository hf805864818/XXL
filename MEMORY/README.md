# MEMORY · 记忆点

这个目录是**项目的大脑**：谁改了什么、为什么这么定、现在到哪一步、哪里还断着，全部记在这里。
代码可以丢，记忆点不能丢。

## 写入规则

| 什么时候写 | 写哪个文件 | 谁写 |
|---|---|---|
| 定下一个技术方案 / 推翻一个方案 | `01-决策记录.md` | 人 |
| 一个阶段做完（编译通过 / 出画面 / 能播动作） | `02-阶段进度.md` | 人 |
| 每次 push 触发构建后（自动） | `03-构建日志.md` | CI |
| 发现新的断点、缺件、踩坑 | `04-已知问题.md` | 人 |
| 素材包结构 / 数量 / 路径契约有变化 | `05-素材规格.md` | 人 |

## 三条铁律

见 `00-项目约定.md`。任何一条被改动，必须同步改那份文档并在 `01-决策记录.md` 记一笔。

## 目录

```
MEMORY/
├── README.md          本文件：怎么用
├── 00-项目约定.md     三条铁律（编译触发 / 版本递增 / 记忆点）
├── 01-决策记录.md     已定方案与理由（D-1 … D-13）
├── 02-阶段进度.md     e1 … e8 状态与通过判据
├── 03-构建日志.md     每次构建一行（CI 自动追加）
├── 04-已知问题.md     断点 / 缺件 / 踩坑 / 待验证项
├── 05-素材规格.md     三类素材的定义与清单
├── 06-越狱兼容.md     Relaxin / RootHide / Dopamine 三越狱适配
└── 07-UI扩展路线.md   运行时面板路线 + 设置页二进制解剖
```

## 一句话

**每次推送前问自己：这一步做完了什么，一句能写进 `02-阶段进度.md` 的话写出来了吗？** 写不出来，说明这一步还没做完。
