## 2. 已修掉的阻断

### 2.1 CODESIGNING 崩溃

- 手工 `lipo -create` 合成的 fat 未重新签名，SpringBoard 加载时 `SIGKILL - CODESIGNING / Invalid Page`，导致注销卡很久、崩溃循环。
- 改用 Theos 生成的 `.theos/obj/debug/PetDFY.dylib`（已签名 fat），崩溃循环消失。

### 2.2 未定义符号导致 dyld 绑定失败

`nm -u` 发现只有 extern、没有实现的符号：

- `_PDNative_MCPResolvedJailbreakPath`
- `_PDNative_MCPRunProcess`
- `__PDNative_MCPGetScreenGeometry`（符号名/返回类型与实现不一致）

已新增 `src/Sources/PDNative_MCPProcess.m` 实现前两个，并修正 `PDNative_MCPAXNodeSource.m` 调用 `PDNative_MCPGetScreenGeometry(PDMCPScreenGeometry *)`。

### 2.3 私有 AX / IOHID 强引用

`_AXUIElementCreateApplication`、`_IOHIDEvent*` 在 SpringBoard 里不保证存在，强引用会让 dylib 加载失败。
已用 `#pragma weak` 把它们改成 weak external：

```text
(undefined) weak external _AXUIElementCreateApplication
(undefined) weak external _IOHIDEventSystemClientCreate
```

## 5. 关于 deb

当前是**手工替换 TweakInject 里的 dylib** 做二分，不是每次重打 deb：

- 好处：迭代快，不用每次传 35 MB。
- 代价：`dpkg` 的 md5 与文件不一致；重新 `dpkg -i` 会覆盖回旧 dylib。
- 结论：**最终验证通过后必须重新打 deb**，把 `PetDFY2`（或修正后的 PetDFY）和素材一起封进去。

## 6. 流程纠正（2026-11-25 08:10）

之前用“手工替换 TweakInject dylib”做二分，导致：
- 版本号不变，无法判断设备上跑的是哪一版；
