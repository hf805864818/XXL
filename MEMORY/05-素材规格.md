# 05 · 素材规格

> 素材分三类，**不要混用**。每类的必备文件、路径契约、数量在这里对齐。

---

## 三类素材

| 类型 | 必备文件 | 能做什么 | 渲染方式 | 现有实例 |
|---|---|---|---|---|
| **服装型** outfit | `model.json`（含 `models.<id>.parts`）+ `originals/outfits/<id>/` | 换装，骨骼不变 | 骨骼 rig + 贴图替换 | 15 套 |
| **动作型** clip | `frames/<action>/NNN.webp` + `clips.plist` | 给骨骼角色加动作 | 整帧位图序列 | 素材 A 116 组 |
| **角色型** character | `frames/` 全量 + `clips.plist` + `catalog.plist` + `mascot.png` | 整只角色替换 | 整帧位图序列（停骨骼） | 小白龙 12 组 |

判定口诀：

- 有 `model.json` + `outfits/` → 服装型
- 只有 `frames/` + `clips.plist`，且是"某个角色的几段动作" → 动作型
- 只有 `frames/` + `clips.plist` + `mascot`，且**构成一个完整角色** → 角色型

## 路径契约（踩过的坑）

1. **帧序以 `clips.plist` 的 `frames` 数组为准**，不要按目录文件名排序 —— 抽帧后编号不连续（`000.webp, 008.webp, 016.webp…`）
2. `clips.plist` 里同一帧可被重复引用（去重时用来保持帧表长度与停留时间）
3. 服装贴图解析链（`PDTextureResolver`）：
   `src → <root>tex/ → <root>outfits/<outfit>/ → originals/outfits/<outfit>/ → <用户包>`
4. 素材根判定：`live/model.json` 存在即视为有效素材根（`PDOverlayController.m:167`）
5. 角色型素材落点：`/var/mobile/Library/Application Support/PetDFY/Characters/<id>/`
6. 素材 A 的 `manifest.json` **没有 `clips` 键**（原版 `asset-manifest.json` 也没有）——
   所以 T3 内置的 `_catalog` 永远是空的，这也是必须外挂帧播放器的原因（D-2）
