# 06 · 越狱兼容

> 目标：**同一份 dylib，在 Relaxin / RootHide / Dopamine 三种 iOS 17 越狱上都能装、都能跑。**
> 对应决策 D-9，对应阶段 e6。

---

## 1. 三种越狱的差异

| 越狱 | 类型 | 安装根 | 关键点 |
|---|---|---|---|
| **Dopamine** | rootless | `/var/jb` | 路径前缀 `/var/jb`；钩子库 ellekit |
| **RootHide** | roothide | `/var/containers/Bundle/Application/.jbroot-<随机>` | 隐藏根，名字随机，**必须运行时探测** |
| **Relaxin** | 待实测 | 见第 4 节 | 不依赖定义，三种根都覆盖 |

共同点：用户数据目录 `/var/mobile/...` **不随越狱类型变化**，变的只是"系统目录（`/Library`）挂在哪"。

---

## 2. 一个 deb 通吃三种根（postinst）

核心逻辑（照 XiaoXiong 1.5.5 的 `deb_ctrl/postinst`）：

```sh
set +e                      # 失败不掩盖
FAIL=0
fail() { FAIL=$((FAIL+1)); say "FAILED: $*"; }

DYN="Library/MobileSubstrate/DynamicLibraries"

# ① 有根：/var/jb 或 /
JB=""
for base in /var/jb /; do
    if [ -d "$base/$DYN" ]; then JB="$base"; break; fi
done
[ -z "$JB" ] && { echo "找不到安装根，请确认已越狱"; exit 1; }

# ② roothide 隐藏根：可能有多个
COUNT=0; CANDS=""
for c in /var/containers/Bundle/Application/.jbroot-* \
         /rootfs/var/containers/Bundle/Application/.jbroot-*; do
    [ -d "$c/Library" ] || continue
    COUNT=$((COUNT+1)); CANDS="$CANDS $c"
done

# ③ 多个候选时不盲选：只认已装我们 dylib 的那个
REAL=""
if [ "$COUNT" -gt 1 ]; then
    for c in $CANDS; do
        [ -f "$c/$DYN/PetDFY.dylib" ] && REAL="$c"
    done
    [ -z "$REAL" ] && { echo "检测到多个 jbroot，无法安全确定安装目标"; exit 1; }
elif [ "$COUNT" -eq 1 ]; then
    for c in $CANDS; do REAL="$c"; done
fi

# ④ 搬运文件到探测到的根
[ -n "$REAL" ] && cp -a payload/* "$REAL/"
```

三条纪律：

| 纪律 | 原因 |
|---|---|
| 日志写私有目录 `0700`、文件 `0600` | 不写固定 `/tmp`，防符号链接截断 |
| 失败计数，不假装成功 | 装挂了要能看出来 |
| 不猜 jbroot | 猜错会把文件写到错误容器 |

## 3. dylib 内的路径改造（必做）

裸写系统路径的代码在 rootless 下会找不到文件。统一走前缀函数：

```objc
// PDPaths.h
static inline NSString *PDJBRoot(void) {
    static NSString *root = nil;
    static dispatch_once_t once;
    dispatch_once(&once, ^{
        if ([[NSFileManager defaultManager] fileExistsAtPath:@"/var/jb/usr/lib"]) {
            root = @"/var/jb";
        } else {
            root = @"";
        }
    });
    return root;
}
static inline NSString *PDSysPath(NSString *rel) {
    return [PDJBRoot() stringByAppendingPathComponent:rel];
}
```

替换清单（T3 现有）：

| 文件 | 现在 | 改为 |
|---|---|---|
| `Core/PDPreferences.m` | `"/Library/PreferenceBundles/..."` | `PDSysPath(@"Library/PreferenceBundles/...")` |
| `Core/PDAssetManager.m` | `"/Library/Application Support/PetDFY.bundle"` | `PDSysPath(...)` |
| `Core/PDZip.m` / `PDSoundPlayer.m` | 可能含 `/usr/bin/unzip` 等 | 用 `PDSysPath(@"usr/bin/unzip")`，找不到再回退系统 |
| 素材下载/导入 | `/var/mobile/Library/Application Support/PetDFY` | **不用改**（用户数据路径不变） |

> 判别口诀：**系统目录加 jbroot，用户数据不加。**

## 4. Relaxin 怎么确认类型

不需要查资料，设备上跑一条命令：

```sh
ls -d /var/jb /var/containers/Bundle/Application/.jbroot-* 2>/dev/null; echo "JBROOT=$JBROOT"
```

| 输出 | 判定 | 按哪种处理 |
|---|---|---|
| 有 `/var/jb` | rootless 类 | Dopamine |
| 只有 `.jbroot-*` | roothide 类 | RootHide |
| 都没有 | rootful | 传统越狱（`/` 可写） |

**结论：因为 postinst 三种根都覆盖，Relaxin 属于哪类都不影响方案**，这条只是用来验证。

## 5. 依赖声明

```control
Depends: firmware (>= 16.0), mobilesubstrate | ellekit | libhooker
Recommends: preferenceloader
```

| 越狱 | 实际满足项 |
|---|---|
| Dopamine | ellekit |
| RootHide | ellekit（roothide 版）或 libhooker |
| 传统 rootful | mobilesubstrate |

用 `|` 是 dpkg 的"或"依赖，任装其一即满足。

## 6. 打包方式（二选一）

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 单包 + 智能 postinst**（推荐） | theos 正常出 rootful 包，postinst 搬到探测到的根 | 一个包装所有越狱 | postinst 复杂，出错要能读日志 |
| B. 出两个包 | `make package` + `THEOS_PACKAGE_SCHEME=rootless make package` | 路径由 theos 处理，postinst 简单 | 两个产物，roothide 还要额外 patcher |

本项目选 **A**。

## 7. 验收清单（e6）

在三种越狱上各跑一遍：

```sh
# 1. 装
dpkg -i PetDFY_*.deb

# 2. 看文件落在哪
ls -l /var/jb/Library/MobileSubstrate/DynamicLibraries/PetDFY.* 2>/dev/null
ls -l /Library/MobileSubstrate/DynamicLibraries/PetDFY.* 2>/dev/null
ls -l /var/containers/Bundle/Application/.jbroot-*/Library/MobileSubstrate/DynamicLibraries/PetDFY.* 2>/dev/null

# 3. 看注入
killall -9 SpringBoard
log stream --predicate 'process == "SpringBoard"' | grep PetDFY

# 4. 卸载
dpkg -r com.ojbkclub.petdfy
```

| # | 判据 | 失败时先看 |
|---|---|---|
| F1 | `dpkg -i` 无错误 | postinst 日志（`/var/mobile/Library/Caches/.../install.*.log`） |
| F2 | 文件出现在正确的根下 | postinst 的 `JB=` / `REAL=` 两行 |
| F3 | 重启后桌宠出现 | 注入过滤器是否也在正确目录 |
| F4 | 卸载后素材与日志仍在 | prerm 是否误删用户目录 |
| F5 | 换越狱类型重装无双份 dylib | 旧根的残留 |

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 装完没反应，日志 `No installation root found` | 越狱未生效或根名不同 | 手动 `ls -d /var/jb` 确认 |
| 日志 `Ambiguous jbroot candidates` | 多个 `.jbroot-*` 且都没有我们的 dylib | 先卸载旧的，或手工指定 |
| 桌宠不出现但 dylib 在 | 注入过滤器路径不对（rootless 下 plist 也要搬） | 检查 plist 是否同目录 |
| 设置页打不开 | PreferenceBundles 未搬或权限不对 | `chmod -R 755` 对应 bundle |
| rootless 下素材找不到 | 代码里裸写了 `/Library/...` | 走 `PDSysPath()` |
